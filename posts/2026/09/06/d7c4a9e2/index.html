Python 项目迁移到 uv：经验小结与可复用工作流

Posted on 2026-09-06 In 技术 , Python Views: Word count in article: 5.8k Reading time ≈ 5 mins.
记录将 Python 项目迁移到 uv 时的关键配置、依赖管理和常见问题，整理一套可复用的迁移工作流。

迁移前要确定的事

  1. Python 版本区间:项目实际验证过的版本
  2. 非默认来源:私有源地址、--extra-index-url、--trusted-host、裸 wheel URL
  3. 当前版本快照:pip freeze > baseline-freeze.txt,迁移后拿它做对照，出问题时也能回滚
  4. 搞清楚两个容易混的概念:.python-version 和 requires-python
    • .python-version:由 uv python pin 生成，决定 uv run、uv sync 用哪个本地解释器
    • requires-python:写在 pyproject.toml 里，决定 uv lock 解析时覆盖的版本区间。区间越窄，锁文件越小

如果要回滚

迁移过程中如果卡住，回滚比继续排查更划算的情况不少见。核心是保留住两样东西:baseline-freeze.txt 和原来的 requirements.txt。

回滚不需要动 pyproject.toml 和 uv.lock——留着它们，下次再迁移时可以从上次中断的地方继续。

uv 常用命令速查

下面按“项目接口”和“uv pip 兼容接口”分类。日常项目优先使用项目接口：它会一起维护 pyproject.toml、uv.lock 和项目虚拟环境；uv pip 则直接操作某个虚拟环境，更适合迁移旧的 requirements.txt 或兼容原有 pip 工作流。

1. 安装、版本与帮助

2. Python 版本管理

uv python pin 只固定本地默认解释器；项目支持哪些 Python 版本，仍由 pyproject.toml 中的 requires-python 决定。

3. 创建项目和虚拟环境

已有 pyproject.toml 时不需要重复执行 uv init，直接补齐 [project] 配置即可。

4. 项目依赖管理

常用选项：

  • --upgrade：允许升级依赖，而不是尽量沿用锁文件中的版本。
  • --no-sync：修改项目依赖或锁文件，但暂不更新 .venv。
  • --locked：要求 uv.lock 已经是最新，否则报错。
  • --frozen：不检查或更新锁文件，适合明确知道后果的临时场景。

5. 锁文件、依赖树和运行命令

uv run 会在运行前检查锁文件和项目环境是否需要同步；CI 中可使用 uv sync --locked，让锁文件不一致时直接失败。

6. 导出、构建和发布

如果项目以 uv.lock 作为唯一锁文件，通常不需要同时长期维护一份手写的 requirements.txt；只有部署系统或旧工具要求时再使用 uv export 导出。
